Bootstrap toasts are lightweight notifications that mimic the push notifications popularized by mobile and desktop operating systems. They utilize flexbox, making them simple to align and position.

## Overview

Things to know when using the toast plugin:

- Toasts are opt-in for performance reasons, so **you must initialize them yourself**.
- Toasts will automatically hide if you do not specify `autohide: false`.

<Callout color="info">
This component's animation effect relies on the `prefers-reduced-motion` media query. For more information, refer to the [reduced motion section of our accessibility documentation](/getting-started/accessibility/#reduced-motion).
</Callout>

## Toaster

<AddedIn version="6.0.0" /> The `Toaster` plugin creates toasts from options, so nothing has to be in the markup up front. It keeps a store of the toasts it shows, keyed by id, and one instance serves the whole page: `add()` returns the id, `update()` rewrites a toast in place, `close()` hides one or all of them, and `promise()` follows an asynchronous operation through its loading, success and error states.

Without an element the toaster creates its own `.toast-container` in `<body>`, placed by the `placement` option; pass an existing container instead to keep control over where the toasts land. The container is a `region` landmark named `Notifications`, so users of assistive technology can navigate to it.

<Example code={`<button type="button" class="btn-solid theme-primary" id="toasterAddBtn">Add a toast</button>
  <button type="button" class="btn-solid theme-secondary" id="toasterUpdateBtn">Update in place</button>
  <button type="button" class="btn-solid theme-secondary" id="toasterPromiseBtn">Follow a promise</button>
  <button type="button" class="btn-solid theme-secondary" id="toasterUndoBtn">With an action</button>
  <button type="button" class="btn-outline theme-secondary" id="toasterCloseBtn">Close all</button>`} sandboxJs={toaster} />

<Code code={toaster} lang="js" />

A toast is a plain options object. `title` renders the header with a close button, `description` the body; a toast without a title puts the close button in the body. `theme` adds the `theme-{color}` class, `timeout` overrides the toaster's default (`0` keeps the toast until it is closed), `priority: 'high'` announces it as an alert instead of a status, and `action` adds a button to the body. Passing an `id` that already exists updates that toast instead of adding a second one, and bumps its `updateKey`, so a "Draft saved" toast clicked twice stays a single toast.

A toast slides in from the container's edge while it fades in — from above in the `top` placements, from below in the `bottom` ones — and slides back out when it closes; the distance is `--cui-toast-slide`. When a toast leaves, or a new one is inserted above the others, the remaining toasts glide into their new positions instead of jumping. Both respect `prefers-reduced-motion`.

`limit` caps how many toasts are visible at once. The newest stay on screen; older ones remain in the DOM with `inert` and `data-coreui-limited`, hidden, and return as the visible ones go away.

Strings are written as text. Set `html: true` on the toaster to render markup; it runs through the same sanitizer as tooltips, configurable with `allowList` and `sanitizeFn`.

## Accessibility

Toasts are meant to be brief interruptions for your visitors or users. To assist those using screen readers and similar assistive technologies, you should wrap your toasts in an [`aria-live` region](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/ARIA_Live_Regions). Changes to live regions, such as injecting or updating a toast component, are automatically announced by screen readers without moving the user's focus or interrupting the user. Additionally, include `aria-atomic="true"` to ensure the entire toast is announced as a single, unfragmented unit, rather than just announcing what changed—this prevents issues if only part of the toast is updated or if the same toast appears again later. If the information is critical to the process, such as a list of form errors, use the [alert component](/components/alerts/) instead of a toast.

Note that the live region must exist in the markup *before* the toast is generated or updated. If you generate both dynamically and inject them simultaneously, assistive technologies generally will not announce them.

You should also adjust the `role` and `aria-live` level based on the content. For important messages like errors, use `role="alert" aria-live="assertive"`; otherwise, use `role="status" aria-live="polite"`.

As the content changes, remember to update the [`delay` timeout](#options) so users have enough time to read the toast.

```html
<div class="toast" role="alert" aria-live="polite" aria-atomic="true" data-coreui-delay="10000">
  <div role="alert" aria-live="assertive" aria-atomic="true">...</div>
</div>
```

When using `autohide: false`, you need to add a close button to let users dismiss the toast.

If you absolutely need to have additional controls, we recommend using a toast with `autohide: false`.

## Usage

Initialize toasts using JavaScript:

```js
const toastElList = document.querySelectorAll('.toast')
const toastList = [...toastElList].map(toastEl => new coreui.Toast(toastEl, option))
```

### Triggers

Dismissal can be achieved with the `data` attribute on a button **within the toast** as demonstrated below:

```html
<button type="button" class="btn-close" data-coreui-dismiss="toast" aria-label="Close"></button>
```

### Options

Options can be passed using data attributes or JavaScript. To do this, append an option name to `data-coreui-`, such as `data-coreui-autohide="{value}"`. Remember to convert the case of the option name from "_camelCase_" to "_kebab-case_" when using data attributes. For instance, you should write `data-coreui-custom-class="beautifier"` rather than `data-coreui-customClass="beautifier"`.

Starting with CoreUI 4.2.6, all components support an **experimental** reserved data attribute named `data-coreui-config`, which can contain simple component configurations as a JSON string. If an element has attributes `data-coreui-config='{"delay":50, "title":689}'` and `data-coreui-title="Custom Title"`, then the final value for `title` will be `Custom Title`, as the standard data attributes will take precedence over values specified in `data-coreui-config`. Moreover, existing data attributes can also hold JSON values like `data-coreui-delay='{"show":50, "hide":250}'`.

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `autohide` | boolean | `true` | Hides the Bootstrap toast automatically |
| `delay` | number | `5000` | Sets delay before hiding the toast (ms) |

### Methods

<Callout color="info">
#### Promises and transitions

**Methods that show or hide a component return a promise.** The promise resolves when the transition ends, so `await` continues at the same moment a `shown.coreui.*` or `hidden.coreui.*` listener runs. The methods still return immediately and never block the caller. A call on a component that is already transitioning does nothing and resolves right away.

[Refer to our JavaScript documentation for further details](/getting-started/javascript/#promises-and-transitions).
</Callout>

| Method | Description |
| --- | --- |
| `dispose` | Hides an element's toast. Your Bootstrap toast will stay in the DOM but won't be visible anymore. |
| `getInstance` | *Static* method that allows you to get the toast instance associated with a DOM element. For example: `const myToastEl = document.getElementById('myToastEl')` and `const myToast = coreui.Toast.getInstance(myToastEl)`. Returns a Bootstrap toast instance.
| `getOrCreateInstance` | *Static* method that gets the toast instance associated with a DOM element or creates a new one if it wasn't initialized. For example: `const myToastEl = document.getElementById('myToastEl')` and `const myToast = coreui.Toast.getOrCreateInstance(myToastEl)`. Returns a Bootstrap toast instance.
| `hide` | Hides an element's toast. **Returns a promise that resolves after the toast is hidden** (i.e., after the `hidden.coreui.toast` event occurs). You need to manually call this method if you set `autohide` to `false`. |
| `isShown` | Returns a boolean indicating the toast's visibility state. |
| `show` | Reveals an element's toast. **Returns a promise that resolves after the toast is shown** (i.e., after the `shown.coreui.toast` event occurs). You need to call this method manually; otherwise, your toast won't appear. |

### Events

| Event | Description |
| --- | --- |
| `hide.coreui.toast` | This event is triggered immediately when the `hide` instance method is called. |
| `hidden.coreui.toast` | This event occurs when the toast has finished hiding from the user. |
| `show.coreui.toast` | This event triggers immediately when the `show` instance method is called. |
| `shown.coreui.toast` | This event occurs when the toast has become visible to the user. |

```js
const myToastEl = document.getElementById('myToast')
myToastEl.addEventListener('hidden.coreui.toast', () => {
  // do something...
})
```

Create a toaster once and keep the instance; every toast on the page goes through it.

```js
const toaster = new coreui.Toaster(null, { placement: 'bottom-end', limit: 3 })
const id = toaster.add({ title: 'Saved', description: 'Your changes are live.', theme: 'success' })
```

#### Toaster options

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `allowList` | object | [Default value](/getting-started/javascript#sanitizer) | Tags and attributes allowed in toast content when `html` is `true`. |
| `container` | string, element | `'body'` | Where the toaster appends the container it creates. Ignored when the toaster is given an existing element. |
| `html` | boolean | `false` | Render `title` and `description` as HTML instead of text. |
| `label` | string | `'Notifications'` | Accessible name of the container's `region` landmark. |
| `limit` | number | `3` | How many toasts stay visible; the oldest beyond it are hidden and `inert` until a slot frees. `0` disables the limit. |
| `placement` | string | `'top-end'` | Corner or edge of the viewport for the container the toaster creates: `top`, `middle` or `bottom` × `start`, `center` or `end`. Toasts in the `top` placements are inserted first, in the others last, so the newest always sits closest to the edge. |
| `sanitize` | boolean | `true` | Sanitize HTML content. |
| `sanitizeFn` | null, function | `null` | Your own sanitizer, used instead of the built-in one. |
| `timeout` | number | `5000` | Default time (ms) before a toast hides. `0` keeps toasts until they are closed. |

#### Toast options

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `action` | object, null | — | `{ label, onClick(event, toast) }` renders a button in the body. |
| `class` | string | — | Extra classes on the `.toast`. |
| `data` | object | — | Anything you want to read back from the toast object later, e.g. in `update(id, previous => …)`. |
| `description` | string, element, function | — | Body of the toast. |
| `dismissible` | boolean | `true` | Render the close button. |
| `id` | string | generated | Stable id; adding with an existing id updates that toast in place. |
| `instant` | boolean | `false` | Skip the fade (`.toast-instant`). |
| `onClose` | function | — | Called when the toast starts hiding, with the toast object. |
| `onRemove` | function | — | Called after the toast left the DOM, with the toast object. |
| `priority` | string | `'low'` | `'low'` renders `role="status"` and `aria-live="polite"`; `'high'` renders `role="alert"` and `aria-live="assertive"`. |
| `theme` | string | — | Adds `theme-{color}`. |
| `timeout` | number | toaster's `timeout` | Time (ms) before this toast hides; `0` keeps it. |
| `title` | string, element, function | — | Header of the toast, with the close button next to it. |
| `translucent` | boolean | `false` | Adds `.toast-translucent`. |

#### Toaster methods

| Method | Description |
| --- | --- |
| `add(options)` | Renders and shows a toast. Returns its id. With an `id` that already exists it behaves like `update`. |
| `update(id, options)` | Rewrites the toast in place and increments its `updateKey`. `options` may be a function receiving the current toast object and returning the changes. |
| `close(id?)` | Hides the toast, which removes it from the DOM and the store once the fade ends. Without an id, hides every toast. |
| `promise(promise, { loading, success, error })` | Adds a toast in the `loading` state and updates it when the promise settles: `success` gets the resolved value, `error` the rejection. Each state is a description string or a full options object, or a function returning either. Returns the promise. |
| `getToasts()` | The toast objects in insertion order, each with `id`, `updateKey`, `limited`, `element` and the options it was created with. |
| `dispose` | Removes every toast, and the container if the toaster created it. |
| `getInstance` | *Static* method that returns the toaster bound to a container element. |
| `getOrCreateInstance` | *Static* method that returns the toaster bound to a container element or creates one on it. |

#### Toaster events

Events fire on the container. Each toast still fires the [toast events](#events) on its own element.

| Event | Description |
| --- | --- |
| `add.coreui.toaster` | Fired after a toast was added; `event.id` is its id. |
| `remove.coreui.toaster` | Fired after a toast left the DOM; `event.id` is its id. |
