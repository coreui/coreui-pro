## Example

Below is an example of a basic Date Picker v2.

### Days

The input is a section-based mask — type the date directly, adjust a section
with the arrow keys, or pick a day from the calendar. There is no free-text
parsing and no debounce: the field always holds a valid partial date.

<Example pro code={`<div class="row">
    <div class="col-sm-6 col-lg-5 mb-3 mb-sm-0">
      <div data-coreui-locale="en-US" data-coreui-toggle="date-picker-v2"></div>
    </div>
    <div class="col-sm-6 col-lg-5">
      <div data-coreui-date="2026/03/15" data-coreui-locale="en-US" data-coreui-toggle="date-picker-v2"></div>
    </div>
  </div>`} />

#### With footer

There is no `footer` option. Project a `<template data-coreui-template="footer">`
child instead — its content is cloned into the dropdown. Buttons act through
`data-coreui-picker-action` (`today`, `clear`, `reset`, `close`), so labels,
order, and translations are yours.

<Example pro code={`<div class="row">
    <div class="col-lg-5">
      <div data-coreui-locale="en-US" data-coreui-toggle="date-picker-v2">
        <template data-coreui-template="footer">
          <button type="button" class="btn btn-sm btn-ghost-danger me-auto" data-coreui-picker-action="today">Today</button>
          <button type="button" class="btn btn-sm btn-ghost-primary" data-coreui-picker-action="clear">Clear</button>
          <button type="button" class="btn btn-sm btn-primary" data-coreui-picker-action="close">OK</button>
        </template>
      </div>
    </div>
  </div>`} />

### Weeks

Add `data-coreui-selection-type="week"` to select week numbers, and
`data-coreui-show-week-number="true"` to show them in the grid.

<Example pro code={`<div class="row">
    <div class="col-lg-5">
      <div
        data-coreui-locale="en-US"
        data-coreui-selection-type="week"
        data-coreui-show-week-number="true"
        data-coreui-toggle="date-picker-v2"></div>
    </div>
  </div>`} />

<Callout color="warning">
  **Week and quarter selection display the underlying date.** A section mask is
  built from date sections (day / month / year), so it cannot render `2026W27`
  or `2026Q1` the way the v1 text input did — the field shows the first day of
  the selected week or quarter instead. The formatted value is still available:
  `event.date` carries `"2026W27"`, `event.dateObject` the `Date`. Dedicated
  week/quarter sections are an open design item for the rewrite.
</Callout>

## Disabled

Add the `data-coreui-disabled="true"` attribute to give the picker a grayed out
appearance and remove pointer events.

<Example pro code={`<div class="row">
    <div class="col-lg-5">
      <div data-coreui-disabled="true" data-coreui-locale="en-US" data-coreui-toggle="date-picker-v2"></div>
    </div>
  </div>`} />

<Callout color="info">
  **`inputReadOnly` and `previewDateOnHover` are gone in v2.** A section field is
  never free-text, so there is nothing to make read-only — use `disabled`. The
  hover preview wrote into the input value, which does not compose with
  sections. See the [migration guide](/migration/v6/).
</Callout>

## Disabled dates

The `disabledDates` option excludes specific dates — single `Date`s,
`[start, end]` ranges, or a matcher function. The calendar grays them out and
the field refuses them: a completed date that hits a disabled entry gets the
`.is-invalid` class and the picker reports `null` until it is corrected.

<Example pro code={`<div class="row">

## Custom formats

`inputDateFormat` and `inputOnChangeDelay` are gone — the mask itself defines
the format. Set it with `data-coreui-format` (or the `format` option), which the
field forwards from the shell. The parser accepts both dayjs/moment-style tokens
(`DD`, `MM`, `YYYY`, `YY`) and date-fns/Unicode-style tokens (`dd`, `MM`,
`yyyy`, `yy`); any other character becomes a literal separator.

<Example pro code={`<div class="row">
    <div class="col-sm-6 col-lg-5 mb-3 mb-sm-0">
      <label class="form-label">dd.MM.yyyy</label>
      <div data-coreui-format="dd.MM.yyyy" data-coreui-locale="en-US" data-coreui-toggle="date-picker-v2"></div>
    </div>
    <div class="col-sm-6 col-lg-5">
      <label class="form-label">YYYY-MM-DD</label>
      <div data-coreui-format="YYYY-MM-DD" data-coreui-locale="en-US" data-coreui-toggle="date-picker-v2"></div>
    </div>
  </div>`} />

A format does not have to include every section — a month-and-year mask reports
the first day of the month.

<Example pro code={`<div class="row">
    <div class="col-lg-5">
      <div data-coreui-format="MMMM yyyy" data-coreui-locale="en-US" data-coreui-toggle="date-picker-v2"></div>
    </div>
  </div>`} sandboxJs={datePickerV2Formats} />

## Usage

### Via data attributes

Add `data-coreui-toggle="date-picker-v2"` to a `div` element.

```html
<div data-coreui-toggle="date-picker-v2"></div>
```

### Via JavaScript

```html
<div class="my-date-picker"></div>
```

```js
const datePickerElementList = Array.prototype.slice.call(document.querySelectorAll('.my-date-picker'))
const datePickerList = datePickerElementList.map(datePickerEl => {
  return new coreui.DatePickerV2(datePickerEl)
})
```

### Options

Options can be passed via data attributes or JavaScript. For data attributes,
append the option name to `data-coreui-`, converting "_camelCase_" to
"_kebab-case_" — write `data-coreui-selection-type="week"`, not
`data-coreui-selectionType="week"`.

Options belonging to the inner [calendar](/components/calendar/#options) or
[date input](/forms/date-input/#options) are forwarded by name, so their data
attributes work on the picker element too.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `allowList` | object | `SVGAllowlist` | Allowlist used when sanitizing the icon markup. |
| `ariaToggleLabel` | string | `'Toggle the calendar'` | Accessible label of the indicator button. |
| `calendarOptions` | object | `{}` | Programmatic escape hatch for calendar options. |
| `container` | string, element, false | `false` | Teleport target for the dropdown. |
| `date` | date, string, null | `null` | Initial value. |
| `disabled` | boolean | `false` | Disables the field and the popup. |
| `indicatorIcon` | string | calendar SVG | Inline SVG rendered by the component (sanitized). |
| `inputOptions` | object | `{}` | Programmatic escape hatch for date input options. |
| `locale` | string | browser locale | Drives section order, separators, and calendar labels. |
| `maxDate` | date, string, null | `null` | Upper bound, enforced by both layers. |
| `minDate` | date, string, null | `null` | Lower bound, enforced by both layers. |
| `name` | string, null | `null` | Name of the generated hidden input. |
| `sanitize` | boolean | `true` | Sanitize the icon markup. |
| `sanitizeFn` | function, null | `null` | Custom sanitizer. |
| `size` | string, null | `null` | `'sm'` or `'lg'`. |

### Methods

| Method | Description |
| --- | --- |
| `show` | Opens the popup. |
| `hide` | Closes the popup. |
| `toggle` | Toggles the popup. |
| `getDate` | Returns the current value (`Date` or `null`). |
| `setDate` | Sets the value and emits `dateChange`. |
| `today` | Sets today's date. |
| `clear` | Clears the value. |
| `reset` | Restores the initial value. |
| `getContext` | Returns the slot context (see below). |
| `dispose` | Destroys the picker and its inner components. |
| `getInstance` | Static — returns the instance for a DOM element. |
| `getOrCreateInstance` | Static — returns the instance, creating it if needed. |

#### Slot context

Projected regions (and any custom code) drive the picker through a small
imperative contract instead of configuration:

```js
const picker = coreui.DatePickerV2.getOrCreateInstance(element)
const context = picker.getContext()

context.today()          // set today's date
context.setDate(date)    // set any date
context.clear()          // clear the value
context.reset()          // restore the initial value
context.close()          // close the popup
context.date             // current value (Date | null)
context.disabled         // disabled state
```

### Events

| Event | Description |
| --- | --- |
| `dateChange.coreui.date-picker-v2` | Fired when the value changes — from the calendar, the field, or a context action. `event.date` carries the new value. |
| `show.coreui.date-picker-v2` | Fired immediately when `show` is called. |
| `shown.coreui.date-picker-v2` | Fired when the popup has been made visible. |
| `hide.coreui.date-picker-v2` | Fired immediately when `hide` is called. |
| `hidden.coreui.date-picker-v2` | Fired when the popup has been hidden. |

The field's own events (`dateChange.coreui.date-input`,
`errorChange.coreui.date-input`) still bubble from the inner element — the shell
does not duplicate them.

```js
const myDatePicker = document.getElementById('myDatePicker')
myDatePicker.addEventListener('dateChange.coreui.date-picker-v2', event => {
  console.log(event.date)
})
```
