## Overview

Create custom `<input type="range" />` controls with `.form-range`. The track (the background) and thumb (the value) are both styled to appear the same across browsers. This is the CSS-only form of the control: it needs no JavaScript and works in any markup the page already has.

<Example code={`<label for="customRange1" class="form-label">Example range</label>
  <input type="range" class="form-range" id="customRange1">`} />

## Filled track

Only Firefox can fill the track up to the thumb from a stylesheet alone, and CSS cannot read an input's value. The fill is drawn a shade lighter than the thumb, at half the strength of `--cui-range-track-fill-bg`. So the filled track is a small **JavaScript component**: wrap an `<input class="form-range-input">` in `.form-range` and the plugin keeps a `--cui-range-fill` custom property (`0`–`1`) in sync on the wrapper, which the CSS uses to draw the fill, the value tooltip and the tick marks.

The `.form-range` wrapper owns the component's tokens, so the input and any decorations inherit them. Every wrapper with a `.form-range-input` inside is initialized automatically.

<Example code={`<label for="range1" class="form-label">Example range</label>
  <div class="form-range">
    <input type="range" class="form-range-input" id="range1">
  </div>`} />

The fill is a single custom property, so a static fill needs no plugin at all: set `--cui-range-fill` on the input yourself.

<Example code={`<label for="rangeStatic" class="form-label">Static fill</label>
  <input type="range" class="form-range" value="40" id="rangeStatic" style="--cui-range-fill: .4">`} />

## Multiple thumbs

Put two or more `.form-range-input` elements in one wrapper to select a range. The inputs stack on one track, the band runs from the lowest thumb to the highest, and each thumb stays a native range input, so dragging, the keyboard, touch, form submission and form reset work as they do for one thumb. The plugin keeps the thumbs in order, moves the nearest one to a press on the track, and keeps the thumb that can still move on top when two of them meet. Give each thumb its own accessible name, because a screen reader cannot tell them apart otherwise.

<Example code={`<label id="rangePriceLabel" class="form-label">Price</label>
  <div class="form-range" data-coreui-tooltips role="group" aria-labelledby="rangePriceLabel">
    <input type="range" class="form-range-input" name="priceMin" value="25" aria-label="Minimum price">
    <input type="range" class="form-range-input" name="priceMax" value="75" aria-label="Maximum price">
  </div>`} />

### Distance

`distance` keeps neighbouring thumbs at least that many units apart.

<Example code={`<div class="form-range" data-coreui-distance="2" data-coreui-tooltips role="group" aria-label="Opening hours">
    <input type="range" class="form-range-input" min="0" max="24" value="8" aria-label="Opens">
    <input type="range" class="form-range-input" min="0" max="24" value="12" aria-label="Lunch">
    <input type="range" class="form-range-input" min="0" max="24" value="18" aria-label="Closes">
  </div>`} />

## Tooltip

Add `data-coreui-tooltips` to the wrapper to show a tooltip with the value that follows the thumb, one per thumb. It appears while the pointer is over the input, while the thumb is held, and while the input has focus. The plugin renders `<div class="form-range-tooltip tooltip bs-tooltip-top">` with `.tooltip-arrow` and `.tooltip-inner`, so it takes the look and the `--cui-tooltip-*` tokens of the [tooltip](/components/tooltips/) component; `tooltipClass` adds classes to it, for example a `theme-{color}`. `tooltipsFormat` may return HTML, which is sanitized, and its text becomes the input's `aria-valuetext`.

<Example code={`<label for="rangeTooltip" class="form-label">Brightness</label>
  <div class="form-range" data-coreui-tooltips>
    <input type="range" class="form-range-input" min="0" max="100" value="60" id="rangeTooltip">
  </div>`} />

Set `data-coreui-tooltips="always"` to keep the tooltip visible at all times.

<Example code={`<label for="rangeTooltipAlways" class="form-label">Brightness</label>
  <div class="form-range mt-4" data-coreui-tooltips="always">
    <input type="range" class="form-range-input" min="0" max="100" value="60" id="rangeTooltipAlways">
  </div>`} />

## Tick marks

Link a `<datalist>` to the input with the `list` attribute and the plugin renders a tick mark for each `<option>`, positioned at its value (even when the values are unevenly spaced). An `<option>`'s `label` is shown beneath its tick, and a labelled tick is drawn taller than an unlabelled one.

<Example code={`<label for="rangeTicks" class="form-label">Temperature</label>
  <div class="form-range">
    <input type="range" class="form-range-input" min="0" max="100" step="25" value="50" list="rangeTicksList" id="rangeTicks">
  </div>
  <datalist id="rangeTicksList">
    <option value="0" label="Cold"></option>
    <option value="25"></option>
    <option value="50" label="Mild"></option>
    <option value="75"></option>
    <option value="100" label="Hot"></option>
  </datalist>`} />

The `ticks` option draws ticks without a datalist, and combines with one: a string is a label, spread evenly with the other strings; a number is a tick without a label at that value; an object sets `value`, `label`, `class` and `style`. A comma-separated `data-coreui-ticks` attribute is a list of labels.

<Example code={`<div class="form-range" data-coreui-ticks="Low, Medium, High" role="group" aria-label="Priority">
    <input type="range" class="form-range-input" value="50" aria-label="Priority">
  </div>`} />

### Clickable ticks

With `clickableTicks`, a press on a tick moves the nearest thumb to its value.

<Example code={`<div class="form-range" data-coreui-clickable-ticks="true" data-coreui-ticks='[{"value": 0, "label": "Cold"}, 25, {"value": 50, "label": "Mild"}, 75, {"value": 100, "label": "Hot"}]' role="group" aria-label="Temperature">
    <input type="range" class="form-range-input" value="25" aria-label="Lowest temperature">
    <input type="range" class="form-range-input" value="75" aria-label="Highest temperature">
  </div>`} />

## Vertical

Add `.form-range-vertical` to the wrapper to stand the control up: the value grows from the bottom, the tooltips sit at the start and the ticks at the end. The height is `--cui-range-vertical-height`.

<Example class="d-flex gap-5" code={`<div class="form-range form-range-vertical" data-coreui-tooltips role="group" aria-label="Volume">
    <input type="range" class="form-range-input" value="60" aria-label="Volume">
  </div>
  <div class="form-range form-range-vertical" data-coreui-tooltips data-coreui-ticks="Low, Mid, High" role="group" aria-label="Frequency band">
    <input type="range" class="form-range-input" value="20" aria-label="Lowest frequency">
    <input type="range" class="form-range-input" value="80" aria-label="Highest frequency">
  </div>`} />

## With form field

Wrap the control in [`.form-field`](/forms/field/) to lay it out with its label and description, and to get validation feedback in the right place. Both forms of the control work there.

<Example code={`<div class="form-field">
    <label for="rangeField" class="form-label">Volume</label>
    <div class="form-range" data-coreui-tooltips>
      <input type="range" class="form-range-input" id="rangeField">
    </div>
    <div class="form-text">Applies to notification sounds only.</div>
  </div>`} />

## Disabled

Add the `disabled` boolean attribute on the input to give it a grayed out appearance, remove pointer events, and prevent focusing.

<Example code={`<label for="disabledRange" class="form-label">Disabled range</label>
  <input type="range" class="form-range" id="disabledRange" disabled>
  <label for="disabledRangeFill" class="form-label mt-3">Disabled range with a filled track</label>
  <div class="form-range">
    <input type="range" class="form-range-input" value="40" id="disabledRangeFill" disabled>
  </div>`} />

## Min and max

Range inputs have implicit values for `min` and `max`—`0` and `100`, respectively. You may specify new values for those using the `min` and `max` attributes.

<Example code={`<label for="customRange2" class="form-label">Example range</label>
  <input type="range" class="form-range" min="0" max="5" id="customRange2">`} />

## Steps

By default, range inputs "snap" to integer values. To change this, you can specify a `step` value. In the example below, we double the number of steps by using `step="0.5"`.

<Example code={`<label for="customRange3" class="form-label">Example range</label>
  <input type="range" class="form-range" min="0" max="5" step="0.5" id="customRange3">`} />

## Theme variants

Color the thumb and the fill by adding a [`.theme-{color}` class](/customize/components/#theme-variants) to the input or a wrapper.

<Example class="d-flex flex-column gap-2" code={getData('theme-colors').map((c) => `<label for="range-${c.name}" class="form-label">${c.title} range</label>
  <div class="form-range theme-${c.name}">
    <input type="range" class="form-range-input" value="60" id="range-${c.name}">
  </div>`)} />

## Usage

The plugin only runs on the wrapper form of the control. A bare `<input class="form-range">` is CSS only and never gets an instance.

### Via data attributes

Every `.form-range` wrapper that contains a `.form-range-input` is initialized on page load—no toggle attribute needed.

| Attribute | Description |
| --- | --- |
| `data-coreui-tooltips` | Add to the `.form-range` wrapper to show a [tooltip](#tooltip) with the value on hover, drag and focus; `"always"` keeps it visible. |
| `list` (on the input) + `<datalist>` | Renders [tick marks](#tick-marks) from the datalist options. |
| `data-coreui-ticks` | Renders [tick marks](#tick-marks) from a comma-separated list of labels. |

```html
<div class="form-range" data-coreui-tooltips>
  <input type="range" class="form-range-input" min="0" max="100" value="40">
</div>
```

### Via JavaScript

```js
const element = document.querySelector('.form-range')
const range = new coreui.Range(element, {
  tooltips: true,
  tooltipsFormat: value => `${value}%`
})
```

### Options

Options can be passed using data attributes or JavaScript. To do this, append an option name to `data-coreui-`, such as `data-coreui-tooltips`.

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `allowList` | object | [Default value](/getting-started/javascript#sanitizer) | Permitted tags and attributes in the HTML that `tooltipsFormat` returns. |
| `clickableTicks` | boolean | `false` | Moves the nearest thumb to a tick's value when the tick is pressed. |
| `distance` | number | `0` | Smallest gap, in value units, between neighbouring thumbs. |
| `sanitize` | boolean | `true` | Sanitizes the HTML that `tooltipsFormat` returns. |
| `sanitizeFn` | null, function | `null` | Replaces the built-in sanitizer. |
| `ticks` | array, boolean, string | `false` | Tick marks in addition to a linked datalist: strings are labels spread evenly, numbers are ticks without a label at that value, objects set `value`, `label`, `class` and `style`. |
| `tooltipClass` | string | `''` | Classes added to every tooltip. |
| `tooltips` | boolean, `'always'` | `false` | Shows a tooltip with the current value of each thumb: `true` on hover, drag and focus, `'always'` at all times. |
| `tooltipsFormat` | function, null | `null` | `(value) => string` that formats the tooltip; HTML is sanitized, and the text becomes the input's `aria-valuetext`. |
| `track` | boolean, `'fill'` | `'fill'` | `false` leaves the track without the band. |

### Methods

| Method | Description |
| --- | --- |
| `dispose` | Destroys the instance, removes the tooltips and tick marks it created, and hands back the attributes and styles it set on the inputs and the wrapper. |
| `getInstance` | Static method which allows you to get the Range instance associated to a DOM element, you can use it like this: `coreui.Range.getInstance(element)` |
| `getOrCreateInstance` | Static method which returns a Range instance associated to a DOM element or create a new one in case it wasn't initialized. You can use it like this: `coreui.Range.getOrCreateInstance(element)` |
| `update` | Recomputes the band, the tooltips and the stacking from the inputs' current values. Useful after setting a value programmatically. |

### Events

| Event | Description |
| --- | --- |
| `changed.coreui.range` | Fired on the input when the value updates (on `input` and `change`). The event's `value` property holds the current numeric value. |

A press on the track or on a clickable tick dispatches the native `input` event on the thumb it moves, and `change` when the pointer is released, the way the browser does when the thumb is dragged.

```js
const input = document.querySelector('.form-range-input')

input.addEventListener('changed.coreui.range', event => {
  console.log('Value:', event.value)
})
```

## Customizing

### CSS variables

`.form-range` carries the tokens, whether it is the input itself or the wrapper. The pseudo-elements that draw the thumb and the track cannot be reached from a stylesheet of your own in every engine, so a token on the input is the way to restyle them:

```css
.form-range.brand {
  --cui-range-thumb-width: 1.5rem;
  --cui-range-track-height: .25rem;
  --cui-range-track-fill-bg: var(--cui-success-base);
}
```

`--cui-range-fill` and `--cui-range-fill-start` are not tokens: the plugin writes them on the wrapper and the CSS reads them, so setting `--cui-range-fill` yourself is how a [static fill](#filled-track) works. The band starts at the track start while `--cui-range-fill-start` is unset.
