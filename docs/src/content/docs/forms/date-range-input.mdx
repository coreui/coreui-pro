## Example

<AddedIn version="6.0.0" />

Use an empty container with `data-coreui-date-range-input` to create a range field. It is two [date inputs](/forms/date-input/) — start and end — and a separator in one frame, held together by the range the component owns: both ends share the mask and the limits, and an end before the start marks the whole field invalid.

<Example pro code={`<label class="form-label">Stay</label>
  <div data-coreui-date-range-input data-coreui-locale="en-US" data-coreui-start-name="check-in" data-coreui-end-name="check-out"></div>`} />

## With form field

Wrap the control in [`.form-field`](/forms/field/) to lay it out with its label and description, and to get validation feedback in the right place.

<Example pro code={`<div class="form-field">
    <span class="form-label">Stay</span>
    <div data-coreui-date-range-input data-coreui-locale="en-US" data-coreui-start-name="check-in" data-coreui-end-name="check-out"></div>
    <div class="form-text">Check-out has to be on or after check-in.</div>
  </div>`} />

## Formats

Set an explicit mask for both ends with the `data-coreui-format` attribute. The parser is the [date input's](/forms/date-input/#formats), so dayjs/moment tokens (`DD`, `MM`, `YYYY`) and date-fns/Unicode tokens (`dd`, `MM`, `yyyy`) both work, and any other character becomes a literal separator.

<Example pro code={`<div class="mb-3">
    <label class="form-label">dd.MM.yyyy</label>
    <div data-coreui-date-range-input data-coreui-locale="en-US" data-coreui-format="dd.MM.yyyy"></div>
  </div>
  <div>
    <label class="form-label">YYYY-MM-DD</label>
    <div data-coreui-date-range-input data-coreui-locale="en-US" data-coreui-format="YYYY-MM-DD"></div>
  </div>`} />

A mask that leaves out sections works here too — a month-and-year range reports the first day of each month:

<Example pro code={`<label class="form-label">Reporting period</label>
  <div data-coreui-date-range-input data-coreui-locale="en-US" data-coreui-format="MM.yyyy"></div>`} />

## Month names

Use the `MMM` or `MMMM` tokens for text month sections in both ends; typing letters matches a month by prefix. Pass all twelve names through `monthNames` to override the locale-derived, date-context grammatical form.

<Example pro code={`<div class="mb-3">
    <label class="form-label">DD MMMM YYYY</label>
    <div data-coreui-date-range-input data-coreui-locale="en-US" data-coreui-format="DD MMMM YYYY"></div>
  </div>
  <div>
    <label class="form-label">Standalone Polish month names</label>
    <div data-coreui-date-range-input data-coreui-locale="pl-PL" data-coreui-format="DD MMMM YYYY"
         data-coreui-month-names='["styczeń", "luty", "marzec", "kwiecień", "maj", "czerwiec", "lipiec", "sierpień", "wrzesień", "październik", "listopad", "grudzień"]'></div>
  </div>`} />

## Initial value

Seed either end with `data-coreui-start-date` and `data-coreui-end-date`; a string is parsed like a typed value.

<Example pro code={`<label class="form-label">Stay</label>
  <div data-coreui-date-range-input data-coreui-locale="en-US" data-coreui-start-date="2026-07-14" data-coreui-end-date="2026-07-20"></div>`} />

## Min and max dates

`minDate` and `maxDate` constrain both ends. A completed date outside the range gets the `.is-invalid` class on its own field and that end reports `null` until the value is corrected.

<Example pro code={`<label class="form-label">Dates in July 2026</label>
  <div data-coreui-date-range-input data-coreui-locale="en-US" data-coreui-format="dd.MM.yyyy" data-coreui-min-date="2026-07-01" data-coreui-max-date="2026-07-31"></div>`} />

## Disabled dates

Beyond a simple range, `disabledDates` excludes specific dates from both ends — single `Date`s, `[start, end]` ranges, or a matcher function. As in the [date input](/forms/date-input/#disabled-dates), a completed date that hits a disabled entry gets `.is-invalid` and that end reports `null`.

In this example July 4–7 and July 16 can't be entered — try typing one of them:

## Validation

The field participates in the standard form validation styling. Four mechanisms set the state:

- **Order (automatic)** — an end before the start is a state of the range, not of either date, so `.is-invalid` lands on the frame and both fields stay editable. `isRangeValid()` reports it.
- **Range validation (automatic)** — a completed date outside `minDate`/`maxDate`/`disabledDates` gets `.is-invalid` on its own field, which the frame picks up.
- **The `valid`/`invalid` options** — force the state on both ends, e.g. after server-side validation.
- **Form submit** — each end renders a hidden input, which is excluded from native constraint validation, so the component applies the state itself when a form with the `data-coreui-validate` attribute is submitted: a `required` empty end becomes `.is-invalid`, and a filled one becomes `.is-valid` when the form opts into success styling with `data-coreui-validate="valid"`.

Sibling `.valid-feedback`/`.invalid-feedback` elements work as with any other form control.

<Example pro code={`<div class="mb-3">
    <div data-coreui-date-range-input data-coreui-locale="en-US" data-coreui-format="dd.MM.yyyy" data-coreui-start-date="2026-07-20" data-coreui-end-date="2026-07-14"></div>
    <div class="invalid-feedback d-block">Check-out has to be on or after check-in.</div>
  </div>
  <div>
    <div data-coreui-date-range-input data-coreui-locale="en-US" data-coreui-format="dd.MM.yyyy" data-coreui-start-date="2026-07-14" data-coreui-end-date="2026-07-20" data-coreui-valid="true"></div>
    <div class="valid-feedback">Looks good!</div>
  </div>`} />

```html
<form data-coreui-validate novalidate>
  <div data-coreui-date-range-input data-coreui-required="true"></div>
  <div class="invalid-feedback">Please provide both dates.</div>
  <button type="submit">Submit</button>
</form>
```

## Composing the markup

The component adopts the parts you write inside its element and generates the rest, so the separator can be a word, your own icon, or nothing you have to configure:

| Role | Element | What the component does with it |
| --- | --- | --- |
| `data-coreui-range-start` | a `div` | Hosts the start field's sections. |
| `data-coreui-range-separator` | any element | Sits between the ends; marked `aria-hidden`, as is an `<svg>` inside it. Without it an arrow is generated from `separatorIcon` / `separatorIconRtl`. |
| `data-coreui-range-end` | a `div` | Hosts the end field's sections. |

<Example pro code={`<div data-coreui-date-range-input data-coreui-locale="en-US">
    <div data-coreui-range-start></div>
    <span class="mx-2 text-body-secondary" data-coreui-range-separator>to</span>
    <div data-coreui-range-end></div>
  </div>`} />

## Accessibility

Each end is a [date input](/forms/date-input/#accessibility) with the spinbutton pattern per section, so the range is two labelled groups rather than one opaque control:

- **Role attributes**: each end has `role="group"`, every section is a `role="spinbutton"` with its value attributes.
- **Names**: the start and end are named separately — `ariaStartLabel` and `ariaEndLabel` by default, or the floating label text when one is set.
- **Separator**: hidden from assistive technology, as is any `<svg>` inside it.
- **Roving tabindex**: each end is a single tab stop; <kbd>Tab</kbd> moves from the start to the end.

### Keyboard support

| Key | Action |
| --- | --- |
| <kbd>0</kbd>–<kbd>9</kbd> | Type into the focused section; the caret advances when the section is complete |
| <kbd>A</kbd>–<kbd>Z</kbd> | In text month sections, match a month name by prefix |
| <kbd>Arrow Up</kbd> / <kbd>Arrow Down</kbd> | Increment / decrement the focused section |
| <kbd>Arrow Right</kbd> / <kbd>Arrow Left</kbd> | Move focus to the next / previous section, crossing the separator from the last section of the start date into the end date and back |
| <kbd>Home</kbd> / <kbd>End</kbd> | Move focus to the first / last section of the focused end |
| <kbd>Backspace</kbd> | Clear the focused section; move to the previous section when already empty |
| <kbd>Delete</kbd> | Clear the focused section |
| <kbd>Tab</kbd> | Move from the start date to the end date |
| <kbd>Ctrl</kbd> + <kbd>A</kbd> / <kbd>Cmd</kbd> + <kbd>A</kbd> | Select the whole value of the focused end |
| <kbd>Ctrl</kbd> + <kbd>V</kbd> / <kbd>Cmd</kbd> + <kbd>V</kbd> | Paste a date into the focused end |

## Usage

### Via data attributes

Add `data-coreui-date-range-input` to an empty `div`. The component renders both fields, the separator, and a hidden input per end for form submission.

```html
<div data-coreui-date-range-input data-coreui-format="dd.MM.yyyy" data-coreui-start-name="from" data-coreui-end-name="to"></div>
```

### Via JavaScript

```javascript
const dateRangeInput = new coreui.DateRangeInput(document.querySelector('#myDateRangeInput'), {
  format: 'dd.MM.yyyy',
  startDate: new Date(2026, 6, 14),
  endDate: new Date(2026, 6, 20)
})
```

### Options

Options can be passed via data attributes or JavaScript. For data attributes, append the option name to `data-coreui-`, as in `data-coreui-start-name="from"`.

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `allowList` | object | SVG allow list | Allowed tags and attributes for the generated separator icon |
| `ariaEndLabel` | string | `'End date'` | Accessible name of the end field when it has no floating label |
| `ariaStartLabel` | string | `'Start date'` | Accessible name of the start field when it has no floating label |
| `autofocus` | boolean | `false` | Focus the first section of the start date right after initialization |
| `disabled` | boolean | `false` | Disable both ends |
| `disabledDates` | array, date, function, null | `null` | Dates (or a matcher function) neither end can hold |
| `endDate` | date, string, null | `null` | Initial end date |
| `endFloatingLabel` | string, null | `null` | Floating label of the end field |
| `endName` | string, null | `null` | Name attribute of the hidden input carrying the end date |
| `format` | function, string, null | `null` | Mask layout for both ends: `null` derives it from the locale, a string is parsed as format tokens, a function receives the locale and returns the section layout |
| `inputDateParse` | function, null | `null` | Custom parser used for pasted text, e.g. a date library |
| `inputOptions` | object | `{}` | Extra options passed to both date inputs |
| `invalid` | boolean | `false` | Force the invalid state (`.is-invalid`) on both ends |
| `locale` | string | browser locale | Locale used to derive the masks and month names |
| `maxDate` | date, string, null | `null` | Latest date either end can hold |
| `minDate` | date, string, null | `null` | Earliest date either end can hold |
| `monthNames` | array, null | `null` | Twelve custom month names for text month sections (`MMM`/`MMMM`) |
| `placeholders` | object, null | `null` | Per-section placeholder overrides, e.g. `{"day": "DD", "month": "MM", "year": "RRRR"}` |
| `readonly` | boolean | `false` | Make both ends focusable but non-editable |
| `required` | boolean | `false` | Required attribute of the hidden inputs |
| `sanitize` | boolean | `true` | Sanitize the generated separator icon |
| `sanitizeFn` | function, null | `null` | Custom sanitizer |
| `sectionLabels` | object, null | `null` | Per-section `aria-label` overrides, e.g. `{"day": "Dzień", "month": "Miesiąc", "year": "Rok"}` |
| `separatorIcon` | string | arrow SVG | Icon of the generated separator; ignored for a `data-coreui-range-separator` you wrote |
| `separatorIconRtl` | string | mirrored arrow SVG | Its right-to-left counterpart |
| `size` | string, null | `null` | `'sm'` or `'lg'` |
| `startDate` | date, string, null | `null` | Initial start date |
| `startFloatingLabel` | string, null | `null` | Floating label of the start field |
| `startName` | string, null | `null` | Name attribute of the hidden input carrying the start date |
| `valid` | boolean | `false` | Force the valid state (`.is-valid`) on both ends |

### Methods

| Method | Description |
| --- | --- |
| `clear` | Empty both ends |
| `getEndDate` | Return the end date, or `null` when that end is incomplete or invalid |
| `getStartDate` | Return the start date, or `null` when that end is incomplete or invalid |
| `isDateSelectable` | Whether a date passes the shared limits |
| `isRangeValid` | `false` while the end is before the start |
| `reset` | Restore the dates the component was created with, emitting the change events when a value moves. A native form reset does the same. |
| `setRange` | Set both ends: `setRange(start, end)`. Each end validates its own date, so what the range keeps is what the fields kept. |

```javascript
const dateRangeInput = coreui.DateRangeInput.getInstance(document.querySelector('#myDateRangeInput'))
dateRangeInput.setRange(new Date(2026, 6, 14), new Date(2026, 6, 20))
dateRangeInput.getStartDate()
dateRangeInput.clear()
```

### Events

| Event | Description |
| --- | --- |
| `endDateChange.coreui.date-range-input` | Fired when the end changes; `event.date` is a `Date`, or `null` when that end is incomplete or invalid |
| `rangeChange.coreui.date-range-input` | Fired once after either end changed; `event.startDate` and `event.endDate` carry the current range |
| `startDateChange.coreui.date-range-input` | Fired when the start changes, with the same payload shape as the end |

```javascript
document.addEventListener('rangeChange.coreui.date-range-input', event => {
  // eslint-disable-next-line no-console
  console.log('Range changed:', event.startDate, event.endDate)
})
```
