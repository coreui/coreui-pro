## Approach

Put `.check` on the `<input type="checkbox">`. That is the whole control — no wrapper, no extra element. Checkboxes are for selecting one or several options in a list; for one option out of many, reach for a [radio](/forms/radio/).

The input and its `<label>` stay siblings rather than the input sitting inside the label, so the label can be styled from the input's state (`:checked`, `:disabled`) with the sibling selector. Relate them with `id` and `for`, and reach for [`.form-field`](/forms/field/) when you want the label, a description and validation feedback laid out for you.

The check and indeterminate marks are drawn with a CSS mask on the input's own `::before`, which is why their colour is a token (`--#{'{'}$prefix{'}'}check-mark-color`) rather than a value baked into an SVG.

## Basic checkbox

<Example code={`<div class="form-field">
    <input class="check" type="checkbox" value="" id="checkDefault">
    <label for="checkDefault">Default checkbox</label>
  </div>
  <div class="form-field">
    <input class="check" type="checkbox" value="" id="checkChecked" checked>
    <label for="checkChecked">Checked checkbox</label>
  </div>`} />

## Indeterminate

Checkboxes can use the `:indeterminate` pseudo-class when it is set from JavaScript — there is no HTML attribute for it.

<Example class="docs-example-indeterminate" code={`<div class="form-field">
    <input class="check" type="checkbox" value="" id="checkIndeterminate">
    <label for="checkIndeterminate">Indeterminate checkbox</label>
  </div>`} />

## Disabled

Add the `disabled` attribute; the associated `<label>` is styled to match, in a lighter color, to indicate the state.

<Example code={`<div class="form-field">
    <input class="check" type="checkbox" value="" id="checkDisabled" disabled>
    <label for="checkDisabled">Disabled checkbox</label>
  </div>
  <div class="form-field">
    <input class="check" type="checkbox" value="" id="checkCheckedDisabled" checked disabled>
    <label for="checkCheckedDisabled">Disabled checked checkbox</label>
  </div>`} />

## Stacked

Any number of checkboxes that are immediate siblings stack vertically and are spaced by `.form-check`.

<Example code={`<div class="form-field">
    <input class="check" type="checkbox" value="" id="defaultCheck1">
    <label for="defaultCheck1">Default checkbox</label>
  </div>
  <div class="form-field">
    <input class="check" type="checkbox" value="" id="defaultCheck2" disabled>
    <label for="defaultCheck2">Disabled checkbox</label>
  </div>`} />

## Inline

There is no inline modifier: the control is an inline element, so a row is a flex container with a gap.

<Example code={`<div class="d-flex gap-3">
    <div class="form-field">
      <input class="check" type="checkbox" id="inlineCheckbox1" value="option1">
      <label for="inlineCheckbox1">1</label>
    </div>
    <div class="form-field">
      <input class="check" type="checkbox" id="inlineCheckbox2" value="option2">
      <label for="inlineCheckbox2">2</label>
    </div>
    <div class="form-field">
      <input class="check" type="checkbox" id="inlineCheckbox3" value="option3" disabled>
      <label for="inlineCheckbox3">3 (disabled)</label>
    </div>
  </div>`} />

## Reverse

Put the box after the label with the `order` utilities.

<Example code={`<div class="form-field">
    <input class="check order-2" type="checkbox" value="" id="reverseCheck1">
    <label class="order-1" for="reverseCheck1">Reverse checkbox</label>
  </div>`} />

## Without a label

A checkbox with no label text is the input on its own. Give it an accessible name some other way — `aria-label`, for instance. See the [forms overview](/forms/overview/#accessibility) for details.

<Example code={`<input class="check" type="checkbox" id="checkboxNoLabel" value="" aria-label="...">`} />

## Description

[`.form-field`](/forms/field/) puts a description under the label and keeps validation feedback in the right place.

<Example code={`<div class="form-field">
    <input class="check" type="checkbox" value="" id="fieldCheck">
    <label for="fieldCheck">Subscribe to the newsletter</label>
    <div class="form-text">We send one email a month, and never share your address.</div>
  </div>`} />

## Toggle buttons

Create button-like checkboxes by putting `.btn` styles on the `<label>` instead of `.form-check-label`, and `.btn-check` on the input. They can be grouped in a [button group](/components/button-group/).

<Example code={`<input type="checkbox" class="btn-check" id="btn-check" autocomplete="off">
  <label class="btn btn-primary" for="btn-check">Single toggle</label>

  <input type="checkbox" class="btn-check" id="btn-check-2" checked autocomplete="off">
  <label class="btn btn-primary" for="btn-check-2">Checked</label>

  <input type="checkbox" class="btn-check" id="btn-check-3" autocomplete="off" disabled>
  <label class="btn btn-primary" for="btn-check-3">Disabled</label>`} />

<Example code={`<input type="checkbox" class="btn-check" id="btn-check-outlined" autocomplete="off">
  <label class="btn btn-outline-primary" for="btn-check-outlined">Single toggle</label>

  <input type="checkbox" class="btn-check" id="btn-check-2-outlined" checked autocomplete="off">
  <label class="btn btn-outline-secondary" for="btn-check-2-outlined">Checked</label>`} />

<Callout color="info">
Visually, these checkbox toggle buttons are identical to the [button plugin toggle buttons](/components/buttons/#button-plugin). However, they are conveyed differently by assistive technologies: the checkbox toggles will be announced by screen readers as "checked"/"not checked" (since, despite their appearance, they are fundamentally still checkboxes), whereas the button plugin toggle buttons will be announced as "button"/"button pressed". The choice between these two approaches will depend on the type of toggle you are creating, and whether or not the toggle will make sense to users when announced as a checkbox or as an actual button.
</Callout>

## Deprecated markup

<span class="badge text-danger-emphasis bg-danger-subtle">Deprecated in v6</span>

The v5 spelling — `.form-check` wrapping a `.form-check-input` and a `.form-check-label`, with `.form-check-inline` and `.form-check-reverse` as modifiers — still works and renders exactly as it did. It is removed in v7, and `$enable-deprecated-form-check: false` leaves it out of your build today.

<Example code={`<div class="form-check">
    <input class="form-check-input" type="checkbox" value="" id="deprecatedCheck" checked>
    <label class="form-check-label" for="deprecatedCheck">
      Deprecated markup
    </label>
  </div>`} />

```diff
- <div class="form-check">
-   <input class="form-check-input" type="checkbox" id="c">
-   <label class="form-check-label" for="c">Label</label>
- </div>
+ <div class="form-field">
+   <input class="check" type="checkbox" id="c">
+   <label for="c">Label</label>
+ </div>
```

See the [v6 migration guide](/migration/v6/) for the full picture.
