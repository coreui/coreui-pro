## Example

The one-time password input is one real text field drawn as separate character slots. Wrap a single `<input>` in a container with `.otp` and add `data-coreui-otp`. The plugin reads the input's `maxlength` for the number of slots, lays the input transparently over the slots and draws one `.otp-slot` per character. Give the input a name with a `<label for>` or `aria-label`.

<Example pro code={`<label class="form-label" for="otpBasic">Verification code</label>
  <div class="otp" data-coreui-otp>
    <input type="text" class="otp-input" id="otpBasic" name="code" maxlength="6" inputmode="numeric" autocomplete="one-time-code">
  </div>`} />

- **One control**: assistive technology announces one text field with one name and one value, not a field per character.
- **Autofill**: `autocomplete="one-time-code"` lets the browser fill a code from an SMS or a password manager.
- **Paste and insert**: a full code pasted, autofilled or inserted at once replaces the field, even a formatted one such as `123-456` or `123 456`; characters the type does not accept and whitespace are dropped, and full-width digits from an input method become digits.
- **Click to edit**: click a slot to select it; the next character replaces it.
- **Keyboard editing**: arrow keys, selection, delete and undo work as in a text field.

## With form field

Wrap the control in [`.form-field`](/forms/field/) to lay it out with its label and description, and to get validation feedback in the right place.

<Example pro code={`<div class="form-field">
    <label class="form-label" for="otpField">Verification code</label>
    <div class="otp" data-coreui-otp>
      <input type="text" class="otp-input" id="otpField" name="code" maxlength="6" aria-describedby="otpFieldText">
    </div>
    <div class="form-text" id="otpFieldText">We sent it to your phone a moment ago.</div>
  </div>`} />

## Code length

The input's `maxlength` sets the number of slots, for example four for a PIN. The `length` option overrides it.

<Example pro code={`<label class="form-label" for="otpPin">PIN</label>
  <div class="otp otp-connected" data-coreui-otp>
    <input type="text" class="otp-input" id="otpPin" maxlength="4">
  </div>`} />

## Groups and separator

Use `data-coreui-groups` to split a code such as `123-456` into groups, and `data-coreui-separator` to change the character between them. The separator is drawn only; the value has no separator. Assistive technology reads the code as one string.

<Example pro code={`<div class="mb-4">
    <label class="form-label" for="otpGroups">Verification code</label>
    <div class="otp otp-connected" data-coreui-otp data-coreui-groups="[3,3]">
      <input type="text" class="otp-input" id="otpGroups" maxlength="6">
    </div>
  </div>
  <div>
    <label class="form-label" for="otpGroupsDash">Licence key</label>
    <div class="otp otp-connected" data-coreui-otp data-coreui-type="alphanumeric" data-coreui-groups="[3,3,3]" data-coreui-separator="-">
      <input type="text" class="otp-input" id="otpGroupsDash" maxlength="9">
    </div>
  </div>`} />

## Types

The input accepts digits by default. Set `data-coreui-type="alphanumeric"` to accept letters and digits, or `data-coreui-type="alpha"` to accept letters only. The type sets the default `inputmode` and `pattern` of the input.

<Example pro code={`<label class="form-label" for="otpAlphanumeric">Code</label>
  <div class="otp otp-connected" data-coreui-otp data-coreui-type="alphanumeric">
    <input type="text" class="otp-input" id="otpAlphanumeric" maxlength="6">
  </div>`} />

## Masking

Set `data-coreui-mask="true"` to draw a dot for each character. The input becomes a password field, so the code cannot be copied and assistive technology does not read it out.

<Example pro code={`<label class="form-label" for="otpMasked">PIN</label>
  <div class="otp otp-connected" data-coreui-otp data-coreui-mask="true">
    <input type="text" class="otp-input" id="otpMasked" maxlength="4">
  </div>`} />

## Paste transformer

`pasteTransformer` is a JavaScript option that turns pasted, autofilled or inserted text before the type filter runs, for example to drop a prefix your messages add.

```javascript
const otp = new coreui.OTPInput(document.querySelector('.otp'), {
  type: 'alphanumeric',
  pasteTransformer: text => text.replace(/^Code:\s*/i, '')
})
```

## Disabled

Add the `disabled` attribute to the input, or call `disable()`.

<Example pro code={`<label class="form-label" for="otpDisabled">Verification code</label>
  <div class="otp otp-connected" data-coreui-otp>
    <input type="text" class="otp-input" id="otpDisabled" maxlength="6" value="123456" disabled>
  </div>`} />

Inside a `<fieldset disabled>` the OTP input shows no error a validation reported, and shows it again once the fieldset is enabled, as a native field does; a state you give stays. To follow the fieldset the component adds a hidden `<coreui-fieldset-watch>` element after its input. It is listed in `form.elements` and `fieldset.elements`, where it shifts the index of the controls after it, and adds nothing to the submitted data.

## Password manager badge

Add `.otp-badge-space` when a password manager draws its badge over the last slot. The class reserves space at the end of the input.

## Validation

The code is validated as the value of the input. The plugin gives the input a `pattern` for the full length, so an incomplete code blocks the submit even when the input is not `required`, and with `required` an empty code blocks it as well; set your own `pattern` on the input to replace it. The browser, or the [form plugin](/forms/validation/#usage) in a form with `novalidate`, puts focus on the input. The state shows on the container as `.is-{state}`, which colors every slot and shows the `.invalid-feedback` that follows the container, and while it is `'invalid'` the input carries `aria-invalid="true"` and is described by that message.

<Example pro code={`<form class="row g-4" data-coreui-validate novalidate>
    <div class="col-12">
      <label class="form-label" for="otpValidation">Verification code</label>
      <div class="otp" data-coreui-otp>
        <input type="text" class="otp-input" id="otpValidation" name="code" maxlength="6" required>
      </div>
      <div class="invalid-feedback">Enter the six digits we sent you.</div>
    </div>
    <div class="col-12">
      <button class="btn btn-primary" type="submit">Verify</button>
    </div>
  </form>`} />

The state comes from three places, in this order:

- The `validationState` option: `'valid'`, `'invalid'` or a state you added to `$form-validation-states`. In the markup, for example from a server that has already checked the code, set it with `data-coreui-validation-state` on the `.otp` element.
- A validation that reports the code invalid: a submit, `checkValidity()` or `reportValidity()`, which the form plugin and the [stepper](/forms/stepper/) call as well. From then on the container shows it invalid whenever the code is invalid, until a native reset of the form. This holds in a form with `data-coreui-validate`, in a form the form plugin validated, in a form with `novalidate` the stepper validated, and outside a form; in any other form the field shows what a native field shows after a blocked submit, the browser's message and the focus, see [Form components](/forms/validation/#form-components).
- In a form with `data-coreui-validate`, the `:user-invalid` state of the input, and with `data-coreui-validate="valid"` also its `:user-valid` state.

A state you give stays until you change it: the user's changes of the code, a native form reset and your own code with `clear()`, `reset()` or `setValue()` keep it. Every change of the code by the user fires `change.coreui.otp-input`: typing or deleting a character, a paste or an autofill. To clear the state when the user changes the code, call `setValidationState(null)` in a `change.coreui.otp-input` listener. A listener there also clears the state on a native form reset and on `clear()` and `reset()`, which fire `change.coreui.otp-input` when they change the code; `setValue()` fires nothing. To change it, call `setValidationState()`. The component does not read `aria-invalid` or a `.is-invalid` or `.is-valid` class on the container or the input. A state class you write there stays yours: it paints the slots, but the input gets no `aria-invalid` and no linked message, see [Form components](/forms/validation/#form-components). A given state does not block the submit; to stop it on your own verdict, call `setCustomValidity()` on the input, as [Form components](/forms/validation/#form-components) shows. A message placed where the stylesheet does not show it for the container can be named in `data-coreui-invalid-feedback` on the `.otp` element. A native reset of the form puts back the code the input started with and keeps the state.

<Example pro code={`<label class="form-label" for="otpServer">Verification code</label>
  <div class="otp" data-coreui-otp data-coreui-validation-state="invalid">
    <input type="text" class="otp-input" id="otpServer" name="code" maxlength="6" value="482910">
  </div>
  <div class="invalid-feedback">This code has expired. Request a new one.</div>`} />

## Accessibility

The control is one text input, so assistive technology announces one field with one name, role and value. The slots are drawn only and hidden with `aria-hidden`.

- **Name**: give the input its name with a `<label for>`, `aria-label` or `aria-labelledby`, and add context with `aria-describedby`.
- **Autofill and keyboard**: the plugin sets `autocomplete="one-time-code"`, the `inputmode` of the type and turns off autocorrect and autocapitalize, unless the input already has them. Write `autocomplete` and `inputmode` in the markup too, so they work before the plugin starts.
- **Groups**: the separator is drawn only; assistive technology reads the code as one string.
- **Masking**: with `mask` the input is a password field, so the characters are not read out and the code cannot be copied.
- **Verification flow**: give codes a generous expiry ([WCAG 2.2.1 Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html)) and do not make users enter a code again that they already gave in the same process ([WCAG 3.3.7 Redundant Entry](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html)).

### Keyboard support

| Key | Action |
| --- | --- |
| <kbd>Arrow Right</kbd> / <kbd>Arrow Left</kbd> | Move to the next or the previous slot. In a right-to-left layout they follow the drawn slots. |
| <kbd>Backspace</kbd> | Delete the character before the caret, or the selected slot |
| <kbd>Delete</kbd> | Delete the character after the caret, or the selected slot |
| <kbd>Tab</kbd> | Enter the field on the first empty slot, or leave it |
| <kbd>Ctrl</kbd> + <kbd>V</kbd> / <kbd>Cmd</kbd> + <kbd>V</kbd> | Paste a code; a complete code replaces the field |
| <kbd>Ctrl</kbd> + <kbd>Z</kbd> / <kbd>Cmd</kbd> + <kbd>Z</kbd> | Undo typing or a paste |

## Usage

### Via data attributes

Add `data-coreui-otp` to a container with `.otp` that holds a single `<input>`.

```html
<div class="otp" data-coreui-otp>
  <input type="text" class="otp-input" name="code" maxlength="6" aria-label="Verification code">
</div>
```

The container takes exactly one input. Markup with a `.form-otp-control` per character, from earlier versions, throws a `TypeError`; see the [migration guide](/migration/v6/).

### Via JavaScript

```javascript
const otpElement = document.querySelector('.otp')
const otp = new coreui.OTPInput(otpElement, {
  type: 'alphanumeric',
  groups: [3, 3]
})
```

### Options

Options can be passed via data attributes or JavaScript. For data attributes, append the option name to `data-coreui-`, as in `data-coreui-type="alpha"`. The input's own attributes give the rest: `name`, `id`, `required`, `disabled`, `readonly`, `placeholder`, `value` and `maxlength`.

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `autoSubmit` | boolean | `false` | Submits the form when the user completes a new code. |
| `groups` | array, null | `null` | Group sizes that get a separator between them, such as `[3, 3]`. |
| `length` | number, null | `null` | Number of slots. With `null` it is read from the input's `maxlength`, and six without one. |
| `mask` | boolean | `false` | Draws a dot (`•`) for each character and makes the input a password field. |
| `pasteTransformer` | function, null | `null` | Turns pasted, autofilled or inserted text before the type filter runs. |
| `separator` | string | `'·'` | Character drawn between groups. |
| `type` | string | `'numeric'` | Accepted characters: `'numeric'`, `'alphanumeric'` or `'alpha'`. Any other value throws a `TypeError`. |
| `validationState` | string, null | `null` | The state the code shows: `'valid'`, `'invalid'` or a state of `$form-validation-states`. `'invalid'` does not block the submit. It stays until you change it. See [Validation](#validation). |

### Methods

| Method | Description |
| --- | --- |
| `clear()` | Clears the code. |
| `disable()` | Disables the input. |
| `dispose()` | Removes the drawn slots and the `inputmode`, `pattern`, `autocorrect`, `autocapitalize` and `spellcheck` the plugin added to an input that had none, and destroys the instance. The input keeps its `maxlength`, `autocomplete` and type. |
| `enable()` | Enables the input. |
| `focus()` | Focuses the input on the first empty slot. |
| `getValue()` | Returns the code. |
| `reset()` | Puts back the code the input started with, as a native form reset does. |
| `setValidationState(state)` | Gives the field a validation state (`'valid'`, `'invalid'` or a state added to `$form-validation-states`), or drops it with `null`. The value stays. See [Validation](#validation). |
| `setValue(value)` | Sets the code; characters the type does not accept are dropped. It fires no event. |

```javascript
const otp = coreui.OTPInput.getInstance(document.querySelector('.otp'))
otp.setValue('123456')
otp.clear()
```

### Events

Treat codes as credentials: keep event values out of logs and analytics.

| Event | Description |
| --- | --- |
| `change.coreui.otp-input` | Fired when the user changes the code, and when `clear()`, `reset()` or a native form reset change it. `setValue()` does not fire it. The event's `value` holds the code. |
| `complete.coreui.otp-input` | Fired when the user completes a new code. The event's `value` holds the code. A reset, `clear()`, `reset()` and `setValue()` do not fire it. |

```javascript
document.querySelector('.otp').addEventListener('complete.coreui.otp-input', event => {
  verifyCode(event.value)
})
```
